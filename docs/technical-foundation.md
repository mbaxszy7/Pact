# Architecture

[Product requirements](product/requirements.md) define behavior, [resource requirements below](#performance-and-resource-requirements) define resource budgets, and [the contribution guide](../CONTRIBUTING.md#testing) defines verification. Read [CONTRIBUTING](../CONTRIBUTING.md) before changing contracts.

## Processes and trust

```text
React Renderer → named DesktopBridge in Preload → Electron Main → Utility Process
                                     ↕ @pact/contracts ↕       → SQLite / native CLIs / Git
```

| Boundary              | Responsibility                                                                                           | Restrictions                                                                                |
| --------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Renderer              | Disposable projections, draft editing, named actions                                                     | Browser code only: no Electron, Node, database, Agent Runtime, or native dependency imports |
| Preload               | Typed `DesktopBridge` and removable subscriptions                                                        | Never expose raw `ipcRenderer`, arbitrary channels, or generic filesystem/process methods   |
| Main                  | Windows, native dialogs/menu/theme, Renderer authorization, Utility transport, bounded Directory workers | Compose feature Modules; keep feature policy in its existing owner                          |
| Utility               | Agent/Git/recording/Undo, probes, image/document processing, persistence                                 | Keep long CPU/I/O work off the streaming event loop when necessary                          |
| `@pact/contracts`     | Strict cross-process DTOs, normalized events, pure workflow rules                                        | Validate inputs, responses, and events at each trust seam; no privileged imports            |
| `@pact/persistence`   | SQLite/Drizzle repositories, atomic facts, Journal, migrations                                           | SQLite is authoritative; no Renderer database access                                        |
| `@pact/agent-runtime` | Provider-neutral `AgentAdapter` interfaces and execution inputs                                          | Native protocols stay private to each desktop Adapter                                       |

`RendererTrust` registers a live Pact window before navigation. Only its current main frame, loaded from the configured development origin or `app://bundle`, can invoke IPC. Packaged builds ignore development URLs. Outgoing publication checks both WebContents and main-frame URLs. Navigation, crash, destruction, close, and disposal release registrations/interests. Popups are denied; approved external links go through the existing Main window owner.

Keep Renderer sandbox, Context Isolation, ASAR integrity, and packaging Fuse restrictions enabled. Treat Project content, tool output, web content, generated text, and native input as untrusted data. Never interpolate user input into shell commands. Spawn executables with argument arrays and `shell: false`. Windows npm `.cmd` compatibility uses constrained fixed `cmd.exe` commands, verbatim arguments, and executable-path metacharacter refusal; it is not a general shell interface.

## Application identities and local builds

One finite registry supplies packaging and Main identities: source launches use local development; local Production stays separate; CI Dev uses `Pact Dev`; Stable uses `Pact`. Packaged identity comes from immutable metadata checked against the registry, version, and native runtime; conflicting profiles fail before Utility starts, and launch environment cannot switch packaged identities. The 16 KiB startup manifest read keeps only validated identity scalars (no queue/retry).

The sole runtime-path owner configures profiles before readiness and the single-instance lock; fixtures create only private profiles. Source development keeps repository-partitioned browser data, `.pact-data/dev/pact.sqlite`, and `Pact/workspace-versions-development/<repository hash>` image/Changes objects; local Production keeps its own profile; CI channels use standard OS roots with no automatic moves/copies/deletes. Managed Project files and native provider homes/auth remain shared.

Packaged Windows AUMIDs come from the registry; source dev appends normalized profile-path SHA256 across process, window, and launch entries while retaining build titles across HTML updates. Mac dev Dock PNG and packaged ICNS share canonical SVG artwork and optical margins; builder names, IDs, and installer names match. Installer release remains gated by platform acceptance.

The dev launcher prepares the Mac bundle before handing off to `electron-vite` in the same Node process (`dev`/`start` only); Windows uses installed Electron. One checkout-local runtime and staging copy bound 8192 entries/1 GiB source, 45 s cancellation deadline, 64 KiB output, and no retry. Plist edits/ad-hoc signing preserve entitlements/fuses. A SHA256 receipt covers executable, plist, registry, ICNS, and launcher; changed inputs regenerate files and failures discard staging. An exclusive lock holds through CLI exit (no queue/stale reclamation; forced termination requires proven exit), adding no migration or resident process.

## Persistence and projections

Drizzle schema files are authoritative. Application queries/writes/CAS/transactions use Drizzle; `better-sqlite3` supplies PRAGMAs, backup, health, and close. Review committed forward migrations/snapshots. `PactDatabase.open` owns startup compatibility and applies pending migrations in Utility before ready; developer migration/Studio use the same entry point and never replace application startup migration. No schema push on application databases.

For disk databases, an exclusive SQLite transaction on the sibling `.pact-writer.sqlite` reserves the canonical data directory before inspection. The owner retains that connection across compatibility checking, backup, migration, business use and physical close. OS process termination releases its file locks; unconfirmed cleanup during opening retains handles and blocks further process opens. This is a cooperative reservation for Pact and the wrapped database tools. It does not exclude arbitrary SQLite clients, legacy tooling or manual filesystem edits that bypass the reservation.

Existing data opens read-only. Verify the ordinary rowid table shape and match every applied row in insertion order to its migration identity and complete SQL-byte SHA256. Divergent, newer, missing or malformed history stops startup with data intact. A proven prefix needs a uniquely reserved consistent backup before writable open, WAL changes or migration.

0105 runs pinned replacement SQL that preserves Session groups (its original digest stays valid only at its original index/timestamp; backup and writable revalidation match observed history). Forward migration `0107_agy_and_active_agent_pairs.sql` adds `secondary_agent_id` (`CHECK (primary_agent_id <> secondary_agent_id)`), `agy_*` model/effort/speed (`'native'`) and permission (`'native'`) columns, three-Agent routing/task/issue columns without fabricating `'agy'` context rows, `handoffRange` `lastAccepted` (`forkSourceRunId IS NULL` matching current `native_agent_contexts`), and `SessionRepository` transactional idle third-Agent replacement gates (verifying zero active/recovering Runs, queued input, unfinished tasks, or unsettled effects, and resetting retiring `'full' -> 'ask'` without mutating locked child side chats).

New databases initialize in a private staging file, verify complete migration history, then publish atomically without overwriting a concurrent file. Existing backups are never overwritten; failed backup targets, migration backups and incomplete initialization files retain their recovery value. Typed startup failure facts cross the Utility/Main seam, where one native prompt offers trusted data-directory entry and quit. Failure triggers no automatic downgrade, replay or reset. Opening/migration bounds are defined in [resource requirements](#application-distribution-and-database-startup).

`PactDatabase` invokes `ConversationRepository.recoverAbandonedBodyInputs` once while it owns startup;
constructing a query projection alone performs no recovery writes. Test-only active observations use
an owned fixture's native readonly connection, without WAL changes or migrations, and explicitly close
their bounded query/lease owner. They cannot acquire or release the application's writer reservation.

### Native presence and resident lifecycle

Main composes one `NativePresence` owner for tray, close-to-hide, Windows JumpList, macOS Dock, navigation and quit confirmation. Show, activation and second-instance events reuse the window (recreating if destroyed); only the current trusted frame invokes schema-validated operations. Launch arguments carry one Session UUID (never profiles, Projects, paths, URLs or provider config). Packaged Windows tasks use the current executable; dev tasks validate the Electron executable, quoted app root, 32-hex identity marker and UUID before the profile lock against the 16 KiB manifest (8192-unit command envelope, 255-unit Windows relaunch limit; mismatched/ownerless dev entries exit `0` before Vite/window startup). Relaunch metadata is set before show; removed tasks match exact executable/canonical prefix; macOS `launch-development` registers the active checkout bundle in LaunchServices and cleans up Dock/Template/Windows overlay resources on disposal unless pending removals require retention.

Before JumpList publication consumes Windows removals, Main durably acknowledges validated removed UUIDs (64-ID bound; overflow/failure retains OS records). SessionWorkspace/repositories own monotonic MRU receipts without directory probes, Adapters or bodies. Side chats (`parent_session_id IS NOT NULL`) stay out of the sidebar catalog and Recent MRU (`recordNativeSessionOpened` no-op) while participating in Needs attention, Running and Quit confirmations (`resolveNativeSession` attaches `resolvedSideChat` alongside parent). Presentation acknowledges only the latest intent; Conversation projects Running rows from live Adapters/references, Starting from preparation, and attention via the shared `SessionIssues` predicate inside atomic Project/global count transactions (zero SQL writes on token progress; unread stays separate). Quit preflight seals admission only when idle, confirms active/uncertain work, bypasses confirmation on OS logout, retains tray/window on unconfirmed exit, and publishes final MRU before DB close and shutdown ACK.

### Archive and other projections

Conversation owns frame-validated archive preparation, readback and cancellation; Renderer owns confirmation and Undo projection; archive repositories own mutations via nonce-bound SQLite receipts and persisted barriers until execution, preparation, native effects and shared `WorkspaceChanges` finalization settle (retaining uncertain barriers across restart; settled failure releases barrier; `scope.kind === 'session'` aggregates parent + child side-chat tasks within the 5-task cap and 16 KiB preview, cascading archive/unarchive). SessionWorkspace commits sidebar visibility, empty-group cleanup and catalog revisions atomically. Main claims the browser profile's single-instance lock before Utility starts (independent across identities/dev checkouts).

`appendAgentEvent` allocates each Session Journal sequence within the same SQL insertion/transaction. Callers must not reserve `MAX(sequence)+1` before nested appends can consume it. Rollback preserves sequence/fact consistency. Journal accompanies repository transitions; it is not yet complete replay or disaster recovery.

Steady mutations produce changed-entity `conversation-patch-v1` Patches, including receipts. Paginated Snapshots serve initial load and explicit resync. Observation incarnation/sequence, body/detail revision, introduction order, and Journal sequence fence different races; they are not interchangeable clocks. Gaps/reordering/new Utility incarnation trigger bounded around/latest reads, preserving reading anchors when possible. Completed Markdown does not reparse on Composer input. Catalog SQL derives latest activity/unread through indexes rather than historical JavaScript aggregation.

Main propagates selected/visible interests through one bounded chain: `useActiveSessionInterest` publishes `{ sessionIds, generation }` (`CONVERSATION_ACTIVE_SESSIONS_PER_VIEWER=2`, supporting simultaneous main + active side chat per viewer, max 8 IDs total across windows) while `useConversation` disables per-instance overwrites when composed. Utility suppresses uninterested body progress while retaining durable facts, terminal/unread/header changes, and receipts. Renderer installs listeners before fetching, awaits interest ACK, and retains only a bounded early-Patch window. Settings keeps one hidden/inert selected Conversation, not per-Session DOM. Reading Retry only reloads pages; it is distinct from Agent Retry. Session replacement retires stale reads/details/navigation/selections.

React Query owns asynchronous Renderer cache/deduplication, pagination, mutation status, and targeted invalidation through centralized keys. It does not own persistent facts, execution state, or token streams. Local UI/drafts stay with their existing React owner; no second workflow store mirrors SQLite.

## Runtime, settings, and catalog

Follow [Readiness](product/requirements.md#readiness), including executable precedence and first-use/degraded behavior. LOCALAPPDATA fences catalogs; recovery only locates. Restart failed Utility; unsettled Session writes allow explicit recovery/readback. Missing results: `Not checked`.

Claude uses SDK `supportedModels()` with idle input; Codex uses initialized App Server `model/list`; Antigravity uses zero-Turn `agy acp --disable-telemetry --log-file` in real user config + `0o700` empty CWD (sibling temp log) with Pact's `clientInfo`, passing through `availableModels`, resolving per-model `thought_level` `configOptions` (defaulting to `[]` when omitted), closing via `session/close`, and cleaning up only that verified zero-step probe's `<sid>.db*`, allowlisted empty-scaffold `brain/<sid>`, and temp log without scanning or deleting user conversation DBs. `DefaultSessionSettings` loads catalogs only for the active `(primaryAgentId, secondaryAgentId)` pair (`recommendedPair` pre-selects Ready CLIs on first use), fences/aborts superseded pair probes per CWD, preserves saved settings of the unselected third Agent, and joins physical child exit before ACK/shutdown. Revalidate concrete Model/Effort without substitution in the target Project.

Canonical path is Project identity enforced by SQLite uniqueness. Root `.git` distinguishes Git/ordinary directories; selection does not promote nested directories/bare repositories. Native editing works under provider permissions for both classes. Archive hides metadata without deleting files/history; re-add restores ID and saved name. Rename changes only display name by primary key and returns a small receipt. An uncertain mutation requires readback before another write, with no automatic repeat.

Session creation copies current global defaults and commits Revision 1 atomically. Later saves create immutable settings revisions; started work keeps its frozen revision, new settings apply to subsequent work. App-default changes do not rewrite existing Sessions. Archive retains history/revisions; no shipped Renderer operation physically deletes Project/Session data. Project removal cannot orphan Sessions.

## Input, routing, and immutable sources

Send freezes body/images, route, Skills, Comment revision and client ID; direct execution also freezes settings. Queue acceptance freezes complete sources without a Run; dispatch freezes current settings. Same-ID retries read their receipt, changed input conflicts, and late ACK preserves newer drafts/IME. Sealing dispatches nothing. Preparation failure preserves input.

Absent explicit routing, Send freezes active Primary; explicit `@claude`/`@codex`/`@agy` targets do not change Session roles, and inactive-Agent mentions/Skills refuse before Message/Run creation. `@all` runs frozen active `[Primary, Secondary]` sequentially (excluding this round's Primary answer from Secondary's input; later Handoffs across `A -> B -> C -> B` deliver unseen history and deltas). `syncSideChatToMain` checks all three `AGENTS` when resolving parent queue anchors and validates `/skill` against the parent's current active target even if the parent swapped in the third Agent after the side chat locked its snapshot.

Peer proposals (`request_peer_assistance`) dynamically expose only `[otherAgent(actor, activePair)]` as validated inert facts, never prose detection or Adapter-to-peer calls. One click authorizes one target Turn while preserving drafts. `PactPeerToolServer` authenticates Antigravity MCP `tools/call` across four root invariants (`_meta["antigravity.google/conversation_id"] === _meta["antigravity.google/root_conversation_id"] === expectedNativeSessionId`, `<trajectoryId>:<stepIdx>` `progressToken`, active `(executorId, bindingGeneration, runId, grant)`, and live `tool_call` completion lifecycle, revoking on root Turn exit) and serves `collaborationSourceAnyReadSchema` (`source:'cutoff'` plus frozen Batch sources).

Body headers/parts preserve original bytes/order/revision/digest. Referenced Message/Run/report material is durable rather than temporary quota data. Segments/references replace whole-Session copying. Native termination, body sealing, and UI publication are distinct. Dependent Handoff/Fork/workflow actions need complete sources. Processing failure retains known terminal/original/partial material and never permits replay. Cold complete-history limits remain in [resource requirements below](#performance-and-resource-requirements); arbitrary-history expansion is not implemented.

Side chats use `sessions.parent_session_id` (self FK cascade delete, `(parent_session_id, created_at, id)` index, `side_chat_origin` `'selection'|'btw'`, anchor columns, `mutation_seq`, and nullability `CHECK` constraints). Side chats start at `New side chat` (`placeholder`), freeze parent settings at creation, seed a deterministic `cutoff_message` draft Comment (`body:''`) on `selection`, reject settings/permission/speed mutations, use standard Agent naming (`requestSessionTitle` / `scheduleTitleEnrichment`), forbid `/plan`/`/build`/`/review`/`/btw` and `Fork`, and reject `/btw` in ordinary `Conversation.send`. `discardEmptySideChat` atomically verifies emptiness across messages, runs, inputs, images, comments, syncs, and restrictive FKs before deleting the untouched session/cutoff and running cutoff GC; `listSideChatsPage` computes `hasUnread`/`unreadCount` from `lastSeenMessageSequence` vs `latestCompleteAssistantSequence`, and `MAX_ADAPTER_SLOTS` idle eviction deprioritizes non-visible side chats below visible/parent main sessions. `captureCutoff` records `O(1)` `conversation_cutoffs` (`source_session_id`, `owner_kind`, `owner_operation_id`, `max_message_sequence`, `session_mutation_seq`, pinning ≤1 streaming message and keeping >64 KiB 8 KiB body segments out of 10-min GC); pre-cutoff `isVisible`/report mutations preserve lazy Copy-on-Write entries in `conversation_cutoff_revisions`. `side_chat_operations` ensures idempotent create/sync receipts. `FrozenSourceReader` authorizes `authorizedCutoffIds` (`source:'cutoff'`, parts `'catalog'|'message'|'comments'`, ≤24 items/48 KiB wire, ≤128 KiB buffer, 1 active/0 queue/10 s, SQLite `substr(CAST(content AS BLOB))` UTF-8 slicing without cross-page WAL readers), paired with a ≤12 KiB `buildCutoffInlineTail` injected once per `(sessionId, agentId, bindingGeneration)` tracked on `nativeAgentContexts.deliveredCutoffIdsJson` (cleared on `bindingGeneration` increment). `@Main` sync-back (`syncSideChatToMain`) bypasses side-chat busy/queue checks (refusing native takeover, recovery, or closing/archived parent), validates parent-agent Skills, shares images zero-copy via `storageObjectId` refcounts (preventing premature file deletion across messages/sessions), mints `'cutoff_message'` Comment anchors in `ConversationRepository.prepareMainSyncBack`, and routes to the parent with `originSideChat` (`liveOriginSideChatTitles` batched lookup keeps synced badges aligned with live renames).

Batches keep all drafts/Comments. NativeObservation owns reader/32B HMAC. Legacy/P1 retain grants; shared reads reject native-root-v1. Current top-level user instructions retain authority; frozen copies and historical/project/tool/anchor data grant none. Ordinary source guidance reads relevant refs; workflows read their complete frozen task/input/source documents without per-member acknowledgements. Internal prompts/protocol IDs stay out of natural Message/Copy/quote display.

## Comments, editor, Skills, and files

Comments are durable Session drafts/sent records. Message anchors retain source SHA, explicit basis (`markdown-visible-v2`, retained v1, or plain fallback), UTF-16 range, and quote. File anchors retain Project-relative path, byte hash, one-based Monaco range, and LF quote. Plan/report anchors retain their original Run and source version. Unsupported historical anchor formats are visibly unavailable; no old task-item UI or source retargeting is inferred. Shared parser/projection rules preserve coordinates with one Text child per projection span. Icons/transformed semantic labels cannot invent quote offsets. Independent discussion Comments remain separate; native form answers stay within their actual transient native interaction. Batch ACK publishes the transaction's actual Comment revision. Returned clones retain private operation provenance outside loaded pages; claim rechecks indexed eligibility before idempotent return.

Document/Session/receipt replacement clears obsolete history. Refused edits preserve original facts. Codex `collaborationMode` resolves model/effort; Plan items are authoritative, deltas previews. ### Admission, transport, and processes

Archive coordination permits at most five in-flight operations with no queue; each preview/receipt
contains at most five distinct task identities. Overflow refuses instead of hiding affected work.
One open preview per Utility expires after 120 s and stores at most 16 KiB; one receipt read is at most
32 KiB. Durable completed/unresolved receipts are not a resident cache or a total-history cap.
One stopping chain has a 15 s monotonic reporting deadline and one 100 ms wait timer; it checks the
bounded existing owners rather than repeatedly scanning a Project. Main archive RPC allows 20 s.
Timeout disables that operation's final commit, preserves unresolved native reservations and reports
unarchived outcomes. Disposal ends the reporting chain; restart reads durable facts without replay.
Scope queries use indexed metadata and primary-key receipt reads; representative SQL and physical
settlement checks remain required independently of build or visual evidence.

Rebuild candidate checks cannot enter a stopping or archived scope; unresolved scopes permit reading
native evidence but not activating a binding. Candidate activation revalidates archive availability
inside its binding transaction after any completed-nonce readback. WorkspaceChanges retains each
finishing Run's recording slot until its directory handle and disposable staging are physically
released; disposal joins the same complete finish promise. A rejected close or staging cleanup
retains the original failed owner and outcome until process exit. Recording preparations and Undo
retain their own existing slots, actual handles, and unreleased scratch credits on cleanup failure;
scope settlement reads all three owners without retrying close, Stop, finalization, or file writes.
An invalidated JavaScript descriptor alone is not evidence of physical release.

Each development/production environment uses10 fixed JSONL slots, each below 5 MiB, within 50 MiB total with 16 KiB reserved metadata (within 20-file retention policy). Retain ≤ 7 days only when ownership safely permits reclamation; live/unknown ownership is never reclaimed by age. Worker I/O/progress/watchdog5 s; close2 s; failed retry30 s; maintenance 60 s. One Debug timer30 min expires at restart. Dispose clears timers/listeners/credits and confirms Worker close. Atomic private slot claims and symlink/hardlink checks cannot be bypassed for quota or convenience.

Measure same fixed stream logging off/on/burst, pressure/ACK loss, total transport/written bytes, concurrent/dead/unknown owners, disk-full/permissions/slow I/O, and 100 close/restart cycles. Encoder-only microbenchmarks are not disk/IPC/packaged latency evidence.
